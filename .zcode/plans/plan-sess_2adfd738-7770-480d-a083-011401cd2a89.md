# 访客接口开放实施计划（B 级 + C 级）

> 决策已对齐：①service 保留 `uuid.UUID` 值语义 + nil 守卫；②不抽取共享 helper；③`/post/home` 组级 OptionalLogin + tab 内分支。

## 目标
把 B 级（8 个零成本只读端点）和 C 级（7 个需小幅改造端点，含 `/post/home`）开放给访客。
**不**触碰 D 级（写操作、个人列表、`/upload/*`、recommend/following 的 tab 内部行为）。

## 设计原则（沿用 qubar-skill 红线）
- handler 层用各域已有的 `requireUserIDAllowAnon` 拷贝（不新增共享包）。
- service 签名保持 `uuid.UUID` 值语义；匿名时 handler 传 `uuid.Nil`，service 内对 `uuid.Nil` 加条件守卫。
- 路由组结构：每域 routes.go 拆成「公开子组（`OptionalLoginFn`）+ 登录子组（`authCheck`）」。
- composition 层：调用方继续传 `authCheck`，由各域 routes.go 自行决定哪些子路由用 `OptionalLoginFn`（与 discover 的 `registerDiscover` 模式一致——discover 是整体丢弃 authCheck；本方案是**部分路由**用 OptionalLoginFn，其余仍用传入的 authCheck）。
- `OptionalLoginFn` 已在 `pkg/composition/auth.go:92`，可直接被各域 routes.go 通过新增参数传入，或在 routes.go 内部引用——**选择后者**（与现有 `registerDiscover` 在 server.go 内切换的写法不同，但更符合「路由注册封装在域内」的 DDD 原则）。

⚠️ **关键约束**：routes.go 在 `interfaces/http` 层，不能 import `pkg/composition`（会循环依赖：composition → interfaces/http）。因此 `OptionalLoginFn` 必须由 composition 在调用 `RegisterRoutes` 时传入。**采用方案**：给需要拆分公开/登录的域的 `RegisterRoutes` 增加一个 `optionalAuthCheck routing.HandlerFunc` 参数，由 composition 传入 `OptionalLoginFn`。

## 分阶段实施

### 阶段 1 — B 级（8 个端点，零 service 改动）

**共性改动**：路由组从 `rg.Group("/xxx", authCheck)` 单组拆为公开子组。

#### 1.1 category 域
- `pkg/domains/category/interfaces/http/routes.go`：`RegisterRoutes` 新增 `optionalCheck routing.HandlerFunc` 参数；`/category/get` 改挂公开组（用 `optionalCheck`）。
- `pkg/composition/server.go` `registerCategory`：传入 `OptionalLoginFn`。
- handler 无改动（`GetCategories` 本就不读 userID）。

#### 1.2 user 域（仅 `/user/search`、`/user/detail/:id`）
- `routes.go`：拆两个子组——公开组（`/search`、`/detail/:id` 用 `optionalCheck`）+ 登录组（`/get`、`/update` 用 `authCheck`）。注意：`GetCurrentUser` 直接读 `c.LoginID()`，匿名访问会 401（这是期望行为，但放在登录组就不会触发）。
- `server.go` `registerUser`：传入 `OptionalLoginFn`。
- handler 无改动。

#### 1.3 circle 域（`/circle/list`、`/active`、`/user`、`/posts`）
- `routes.go`：拆公开组（list/active/user/posts）+ 登录组（create/detail/my/join/leave）。`detail` 走 C 级（阶段 2）。
- `server.go` `registerCircle`：传入 `OptionalLoginFn`。
- handler 无改动。

#### 1.4 post 域（`/post/list`、`/post/user/:user_id`）
- `routes.go`：拆公开组（list/user）+ 登录组（create/my/detail）。`detail` 走 C 级。
- `server.go` `registerPost`：传入 `OptionalLoginFn`。
- handler 无改动。

### 阶段 2 — C 级（7 个端点，service 加 nil 守卫）

#### 2.1 comment 域（list/replies/detail）— **零 service 改动**
- handler 已用 `requireUserIDAllowAnon`，service 已 best-effort。
- `routes.go`：把 list/replies/detail 移到公开组；create 留登录组。
- `server.go` `registerComment`：传入 `OptionalLoginFn`。

#### 2.2 circle 域 `/circle/detail/:id`
- handler `GetCircleDetail`（`handler.go:96`）：`requireUserID` → `requireUserIDAllowAnon`。需在该 handler 文件新增一份 `requireUserIDAllowAnon`（与 comment/discover 同款）。
- service `GetCircleDetail`：**无需改动**——`memberRepo.GetMember(ctx, circleID, uuid.Nil)` 返回 `ErrMemberNotFound`，`IsJoined` 保持 false，天然降级（`service.go:459-470`）。可选择加一行早返优化（userID==Nil 时跳过 GetMember DB 查询），但非必需。
- routes.go：detail 移入公开组（与 1.3 合并）。

#### 2.3 post 域 `/post/detail/:id` — **重点改造**
- handler `GetPostDetail`（`handler.go:62`）：`requireUserID` → `requireUserIDAllowAnon`。新增 helper 拷贝。
- service `GetPostDetail`（`service.go:429`）：
  - `service.go:446-454` 异步 goroutine：加 `if userID != uuid.Nil` 守卫，**防止匿名把 uuid.Nil 写入 `user:view:posts:{00000000-...}` 污染历史池 + 防 IncrViewCount 用 uuid.Nil 作去重 key**。
  - `service.go:441` `checkLiked` / `service.go:444` `checkCollected`：加 `if userID == uuid.Nil { 直接返回 false }` 早返，避免对 uuid.Nil 做无意义 DB/Redis 查询。
  - `service.go:436` 作者可见性检查：`userID != post.UserID`——匿名(uuid.Nil)天然走「非作者→只看 published」分支，**无需改动**。
- routes.go：detail 移入公开组（与 1.4 合并）。

#### 2.4 trending 域 `/trending/`
- handler `GetTrending`（`handler.go:44`）：`requireUserID` → `requireUserIDAllowAnon`，删除「热点页强制登录」注释。新增 helper 拷贝。
- service `GetTrending`：**无需改动**——`fillPosts` 的 `checker.BatchCheck(ctx, uuid.Nil, ids)`（`service.go:137`）已是 best-effort（失败时 liked/collected 为 nil，`service.go:150-155` 的 nil 守卫保证不 panic）。
- routes.go：整个 `/trending` 组换 `optionalCheck`。
- `server.go` `registerTrending`：传入 `OptionalLoginFn`。

#### 2.5 post/home 域（recommend）— **tab 内分支**
- handler `GetHomeFeed`（`handler.go:36`）：`requireUserID` → `requireUserIDAllowAnon`，删除「推荐流强制登录」注释。新增 helper 拷贝。
- service `GetHomeFeed`（`service.go:67`）：在 tab 分发的 `case "recommend"` / `case "following"` 分支前加 nil 守卫——`userID == uuid.Nil` 时返回新哨兵错误 `ErrLoginRequired`。hot/latest 放行（`getSimpleFeed` 的 BatchCheck 对 uuid.Nil 是 best-effort，安全）。
- application 层新增 `ErrLoginRequired` 哨兵 + `IsLoginRequiredErr` 谓词（`pkg/domains/recommend/application/errors.go`）。
- handler `writeXxxError` 映射 `ErrLoginRequired` → `httputil.Unauthorized`。
- routes.go：`/post/home` 当前挂在 `/post` 组下，由 post 域 routes.go 注册——**关键**：recommend 域 routes.go 是独立 `RegisterRoutes`，挂的是 `/post` 组（`recommend/interfaces/http/routes.go:25`）。需把 `/post/home` 单独移到公开子组（用 `optionalCheck`），而 post 域自己的 `/post/list`、`/post/user/:user_id` 已在阶段 1.4 移到 post 公开组。**两域都注册在 `/post` 前缀下**——需确认是否冲突，检查 hertz 路由注册行为（同一前缀两个组应可共存，但需验证）。

## ⚠️ 风险点与验证清单

| 风险 | 验证方式 |
|---|---|
| post 异步历史污染（uuid.Nil 写入） | service.go:446 加 nil 守卫；`go build ./...` + 人工 review |
| `/post` 前缀被 post 和 recommend 两域注册 | 检查 `recommend/interfaces/http/routes.go` 实际前缀；若冲突，recommend 的 `/post/home` 改由 post 域 routes.go 统一注册（合并到 post 公开组） |
| service 签名不变是否破坏现有调用 | 全部桥接器（composition）传值不变；uuid.Nil 在登录路径不会出现（OptionalLogin 登录成功才 SetLoginID） |
| hot/latest tab 匿名时 BatchCheck 行为 | 已确认 best-effort，uuid.Nil 查空 map → IsLiked/IsCollected=false |
